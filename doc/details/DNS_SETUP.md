# Настройка DNS для Caddy (Let's Encrypt)

Перед установкой TlibWebApp с Caddy необходимо настроить DNS запись вашего домена.

## Зачем это нужно

Caddy автоматически получает HTTPS сертификат от Let's Encrypt. Для этого Let's Encrypt проверяет, что домен действительно принадлежит вашему серверу — он делает HTTP-запрос к домену и ожидает ответ от Caddy.

**Если DNS не настроен** → Let's Encrypt не сможет связаться с сервером → сертификат не выдадут → Caddy не запустится корректно.

---

## Шаг 1: Узнайте IP адрес сервера

Подключитесь к серверу по SSH и выполните:

```bash
# Внешний IP (для VPS/облачного сервера)
curl -4 ifconfig.me

# Или локальный IP (для сервера в локальной сети)
hostname -I | awk '{print $1}'
```

Запишите полученный IP адрес, например: `203.0.113.50`

---

## Шаг 2: Создайте DNS запись

Войдите в панель управления вашего домена (регистратор или DNS-хостинг) и создайте **A-запись**:

| Поле | Значение |
|------|----------|
| **Тип** | A |
| **Имя/Host** | `@` (корневой домен) или поддомен (например `tlib`) |
| **Значение/IP** | IP адрес вашего сервера |
| **TTL** | 300 или "Авто" |

### Примеры

**Корневой домен** (`example.com`):
```
Тип: A
Имя: @
IP: 203.0.113.50
```

**Поддомен** (`tlib.example.com`):
```
Тип: A
Имя: tlib
IP: 203.0.113.50
```

### Инструкции для популярных провайдеров

<details>
<summary><b>Cloudflare</b></summary>

1. Войдите в [dash.cloudflare.com](https://dash.cloudflare.com)
2. Выберите домен → **DNS** → **Records**
3. Нажмите **Add record**
4. Заполните:
   - Type: `A`
   - Name: `@` или имя поддомена
   - IPv4 address: IP вашего сервера
   - Proxy status: **DNS only** (серая иконка облака)
5. Нажмите **Save**

> **Важно:** Отключите Proxy (оранжевое облако), иначе Let's Encrypt не сможет проверить домен.

</details>

<details>
<summary><b>REG.RU</b></summary>

1. Войдите в [reg.ru](https://www.reg.ru) → Личный кабинет
2. Домены → выберите домен → **DNS-серверы и управление зоной**
3. Нажмите **Добавить запись**
4. Заполните:
   - Тип: `A`
   - Subdomain: оставьте пустым для корневого или введите имя поддомена
   - IP Address: IP вашего сервера
5. Нажмите **Добавить**

</details>

<details>
<summary><b>Timeweb</b></summary>

1. Войдите в [timeweb.com](https://timeweb.com) → Панель управления
2. Домены → выберите домен → **DNS**
3. Нажмите **Добавить запись**
4. Заполните:
   - Тип: `A`
   - Хост: `@` или имя поддомена
   - Значение: IP вашего сервера
5. Сохраните

</details>

<details>
<summary><b>Другие провайдеры</b></summary>

Общий алгоритм:
1. Найдите раздел "DNS", "Зона DNS" или "DNS Records"
2. Добавьте новую запись типа **A**
3. В поле имени укажите `@` (корень) или имя поддомена
4. В поле значения укажите IP адрес сервера
5. Сохраните изменения

</details>

## Шаг 3: Дождитесь распространения DNS

DNS изменения распространяются по интернету не мгновенно.

**Типичное время:**
- Cloudflare: 1-5 минут
- Другие провайдеры: 5-30 минут
- Максимум (редко): до 24-48 часов

### Проверка готовности

**На сервере:**
```bash
# Проверка через nslookup
nslookup tlib.example.com

# Проверка через dig (если установлен)
dig +short tlib.example.com
```

Ожидаемый результат — IP адрес вашего сервера.

**Онлайн-сервисы:**
- [dnschecker.org](https://dnschecker.org) — проверка распространения по всему миру
- [whatsmydns.net](https://www.whatsmydns.net) — аналогичный сервис

Когда большинство серверов показывают ваш IP — можно продолжать установку.

---

## Шаг 4: Продолжите установку

После успешной проверки DNS вернитесь к установке:

```bash
cd /opt/TlibWebApp
./tools/install_ubuntu_caddy.sh tlib.example.com admin@example.com
```

## Troubleshooting

### "DNS resolution failed" или сертификат не выдаётся

1. Проверьте что DNS запись создана правильно
2. Убедитесь что IP в DNS совпадает с IP сервера
3. Подождите ещё 10-15 минут
4. Если используете Cloudflare — отключите Proxy (оранжевое облако → серое)

### "Connection refused" при проверке

Порты 80 и 443 должны быть открыты на сервере:
```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

### Домен резолвится, но Caddy не получает сертификат

Проверьте логи Caddy:
```bash
sudo journalctl -u caddy -n 100
```

Частые причины:
- Firewall блокирует входящие соединения
- Порт 80 занят другим процессом (`sudo lsof -i :80`)
- Сервер за NAT без проброса портов
