# Обмен доменами turclub.com и tlib.ru

Короткая инструкция, как поменять домены местами: новый сайт (этот проект) станет `tlib.ru`, а старый сайт — `turclub.com`. Сами компьютеры и установленный на них код не трогаем — меняем только DNS.

## Главное (3 правила)

1. Машины и код остаются на месте. Меняются только DNS-записи: `tlib.ru` начинает указывать на машину с новым кодом, `turclub.com` — на машину со старым.
2. На новой машине обязательно поменять `SITE_URL` на `https://tlib.ru` и перезапустить приложение. Иначе сайт будет подсказывать поисковику чужой адрес.
3. Старые ссылки вида `tlib.ru/doc.aspx?id=12345` новый код перенаправит на новую страницу отчёта сам — отдельно ничего настраивать не нужно.

## Порядок действий (коротко)

1. Поменять DNS (обменять адреса доменов).
2. На новой машине: перенастроить Caddy на `tlib.ru` и поменять `SITE_URL`.
3. На старой машине: закрыть сайт от индексации (`robots.txt`).
4. Проверить в браузере.
5. Обновить Яндекс.Вебмастер.

Ниже каждый шаг подробнее.

## 1. Что сделать в новом коде (машина, которая станет tlib.ru)

Эта машина сейчас обслуживает `turclub.com`. Нужно два изменения.

### 1.1. Переключить Caddy на новый домен

Caddy выдаёт HTTPS-сертификат под конкретный домен, поэтому его надо перенастроить на `tlib.ru`. Проще всего заново запустить установочный скрипт с новым доменом:

```bash
cd /opt/TlibWebApp
./tools/install_ubuntu_caddy.sh tlib.ru tlibkeeper@gmail.com
```

Скрипт перезапишет `/etc/caddy/Caddyfile` под `tlib.ru` и перезапустит Caddy. Сертификат Let's Encrypt выпустится автоматически, как только DNS начнёт указывать на эту машину (может занять несколько минут — короткое предупреждение о сертификате в это время нормально).

Вручную как альтернатива: открыть `/etc/caddy/Caddyfile`, в первой строке заменить `turclub.com` на `tlib.ru`, сохранить и выполнить `sudo systemctl restart caddy`.

### 1.2. Поменять SITE_URL

1. Открыть файл `data.secret/.env`.
2. Найти строку `SITE_URL=...` и поставить:

   ```
   SITE_URL=https://tlib.ru
   ```

3. Сохранить и перезапустить приложение:

   ```bash
   sudo systemctl restart tlibapp
   ```

От `SITE_URL` автоматически зависят адреса в `sitemap.xml`, теги canonical, `robots.txt` и ссылки в письмах — их править вручную не нужно.

Больше на новой машине для смены домена ничего не требуется (вход по cookie, защита и заголовки от домена не зависят).

## 2. Что сделать в старом коде (машина, которая станет turclub.com)

Старый сайт остаётся доступным на `turclub.com`, но его нужно закрыть от поисковиков — иначе он будет дублировать `tlib.ru` (там тот же каталог отчётов) и мешать ему в выдаче.

1. Настроить, чтобы машина отвечала на домен `turclub.com` по HTTPS (как обычно настраиваете домен и сертификат на этой машине).
2. Положить в корень сайта файл `robots.txt` ровно из двух строк:

   ```
   User-agent: *
   Disallow: /
   ```

Это запрещает поисковикам индексировать старый сайт. Сам сайт при этом продолжает открываться у людей по ссылкам.

Примечание (KISS): пара старых адресов `turclub.com` может какое-то время оставаться в поиске как «закрытые». Трафик там незначительный (он на `tlib.ru`), поэтому таким мелким остатком осознанно жертвуем ради простоты.

## 3. Что сделать в Яндекс.Вебмастере

Для `tlib.ru` (главный сайт):

1. Индексирование → Файлы Sitemap → добавить `https://tlib.ru/sitemap.xml`.
2. Индексирование → Проверка ответа сервера → ввести любой старый адрес, например `https://tlib.ru/doc.aspx?id=28466` — ответ должен быть «301» с переадресацией на страницу отчёта `/?<шифр>`.
3. Сайт `tlib.ru` из Вебмастера не удалять.
4. По желанию: проверить регион (Москва) и отправить главную страницу на переобход.

Для `turclub.com`: ничего отдельного делать не нужно — он закрыт `robots.txt` и со временем выпадет из поиска сам.

Важно: переиндексация в Яндексе занимает 2–4 недели. Временная просадка трафика на 10–20% в первые недели — это нормально, не пугайтесь.

## 4. Что ещё

### DNS (сам обмен)

У регистратора (в панели управления DNS) поменять A-записи (IP-адреса):

- `tlib.ru` → IP машины с новым кодом;
- `www.tlib.ru` → туда же (или CNAME на `tlib.ru`);
- `turclub.com` → IP машины со старым кодом.

Прежние значения запишите заранее — пригодятся для отката.

### Проверка после переключения (в браузере)

- `https://tlib.ru` — открывается новый дизайн, замок HTTPS целый.
- `https://tlib.ru/sitemap.xml` — открывается список адресов.
- `https://tlib.ru/doc.aspx?id=<реальный_старый_id>` — перекидывает на страницу отчёта.
- `https://turclub.com` — открывается старый сайт.

### Если что-то пошло не так (откат)

Так как код и машины не меняли, откат простой: вернуть DNS-записи к прежним значениям. Через некоторое время (зависит от DNS) всё вернётся как было.

### Не торопиться убирать

- Перенаправления старых адресов и `robots.txt` на `turclub.com` держать минимум 12 месяцев.
- Мелочь: убедиться, что `wiki.tlib.ru` открывается по HTTPS (после переезда браузеры будут требовать HTTPS на поддоменах `tlib.ru`).
